# مدار — عرض إدارة طلبات الخدمات الإلكترونية

نموذج عربي تفاعلي باتجاه RTL للشركات والتجار، مبني بـ React وTypeScript وVite وReact Router وTailwind CSS وLucide. الخط العربي محلي ضمن حزمة التطبيق. لا يوجد خادم خلفي أو مصادقة حقيقية أو معاملات مالية.

## التشغيل

يتطلب Node.js حديثاً (يفضل 22 أو أحدث).

```sh
npm install
npm run dev
```

افتح http://127.0.0.1:5173. لبناء نسخة الإنتاج: `npm run build`، ولمعاينتها: `npm run preview`، وللاختبارات: `npm test`.

## المسارات

| المسار | الشاشة |
| --- | --- |
| `/` | الرئيسية والإحصاءات والنشاط |
| `/requests` | الطلبات والبحث والتصفية |
| `/requests/new` | إنشاء الطلب؛ يدعم `company` و`service` في الرابط |
| `/requests/:id` | تفاصيل الطلب وتنفيذه ومرفقاته وسجله |
| `/companies` و`/companies/:id` | الشركات والحسابات والموظفون والبطاقات والطلبات |
| `/cards` و`/cards/:id` | سجل البطاقات والإضافة اليدوية وتاريخ العمليات |
| `/services` | الخدمات السبع |
| `/reports` | ملخص إحصائي مباشر |
| `/settings` | معلومات العرض وإعادة تعيين البيانات |

## أدوار العرض

يتم التبديل من أعلى الشاشة، ويحفظ الاختيار محلياً:

- أحمد محمد — موظف استقبال الطلبات: الإنشاء والمتابعة وإلغاء الطلب المنتظر مع سبب.
- محمد سالم — موظف تشغيل البطاقات: بدء التنفيذ، تسجيل البطاقات ونتائج العمليات، رفع الكشف، الإكمال والرفض.
- فاطمة علي — مشرف النظام: جميع الإجراءات وإعادة تعيين بيانات العرض.

التحقق من الصلاحيات موجود في المستودع إضافة إلى الواجهة، لكنه محاكاة أمامية وليس آلية أمان إنتاجية.

## البيانات والحفظ

`src/data/seed.json` يحتوي على خمس شركات، وحساب لكل شركة، و15 موظفاً، وبطاقات شركة وموظفين، و28 طلباً متنوع الحالة، وخدمات وسجلات ومرفق محاكى. كل المعلومات خيالية. تواريخ البداية ثابتة في سبتمبر 2026؛ إحصاء طلبات اليوم يعتمد على تاريخ التشغيل الفعلي.

النماذج في `src/models/index.ts`. تتعامل الشاشات مع `src/services/repository.ts` فقط؛ يحفظ المستودع النسخة تحت `madar-bank-demo-v1` في localStorage. تتم كتابة التغيير بالكامل قبل اعتماده في الذاكرة، ويظهر خطأ عربي إذا امتلأت مساحة المتصفح. إعادة التعيين من الإعدادات تتطلب دور المشرف وتأكيداً، وتعيد JSON الأصلي وتحذف التغييرات والمرفقات المحلية.

الواجهات لا تخزن رقم البطاقة الكامل؛ تحفظ آخر أربعة أرقام والمرجع. لا توجد حقول PIN أو CVV. البطاقة الصادرة ترتبط بالطلب والشركة والموظف إن وجد. الاستبدال ينشئ بطاقة جديدة مرتبطة بالأصل ويغيّر حالة الأصل عند إكمال الطلب، مع حفظ التاريخ. تغيير الحالة والتسليم يطبقان عند إكمال الطلب فقط.

يمكن استبدال المستودع لاحقاً بمحول REST لـ ASP.NET Core دون توزيع التعامل مع التخزين على المكونات. لا توجد حالياً قاعدة بيانات أو مزامنة مع نظام البطاقات.

## المرفقات والعمليات المحاكاة

العمليات الخارجية (الإصدار والشحن والرمز السري وكشف الحساب) تنفذ خارج هذا النموذج ويقوم المستخدم بتوثيق نتائجها. الشحن الفاشل لا يمكن إكماله كعملية ناجحة؛ يمكن تصحيح النتيجة أو رفض الطلب مع السبب.

`src/services/attachments.ts` يقرأ PDF فعلياً بحد أقصى 1 ميغابايت لكل ملف ويحفظه ضمن بيانات المتصفح، بحيث تستمر المعاينة والتحميل بعد تحديث الصفحة. إجمالي الملفات خاضع لمساحة localStorage. مرفق بيانات البداية مجرد بيانات وصفية مع معاينة توضيحية، وموسوم كمحاكاة؛ لا يدعي تحميل كشف حقيقي. ارفع ملف PDF لتجربة التخزين والتحميل الفعليين.

## خطوات عرض مقترحة

1. كموظف استقبال، أنشئ طلب إصدار لموظف في شركة النور.
2. بدّل لموظف التشغيل، وافتح الطلب وابدأ التنفيذ بتأكيد الحوار.
3. سجل آخر أربعة أرقام ومرجع البطاقة والاسم وتاريخي الإصدار والانتهاء، ثم أكمل الطلب.
4. افتح الشركة ثم تبويب الموظفين أو البطاقات للتحقق من الارتباط.
5. أضف بطاقة موجودة من شاشة البطاقات؛ بدّل للاستقبال وأنشئ لها طلب رمز سري.
6. جرّب بدل الفاقد والشحن والكشف بالطريقة نفسها. يجب حفظ نتيجة الشحن قبل الإكمال، وإرفاق PDF للكشف.
7. جرّب الرفض مع سبب ثم راجع السجل. استخدم المشرف لإعادة التعيين قبل العرض التالي.

## التحقق

اختبارات المستودع تغطي السيناريوهات A–F والحفظ بعد إنشاء مستودع جديد، والصلاحيات، وعزل الشركات، وإلغاء الطلبات، وتغيير الحالة، والتسليم، وإعادة التعيين وفشل التخزين. اختبارات عرض المسارات تتحقق من عرض الصفحات والخدمات السبع دون أخطاء. الاختبارات لا تعوض المراجعة البصرية أو النقر اليدوي داخل متصفح؛ لم يتوفر متصفح متصل أثناء التنفيذ.
